# Планирование: анализ, идентификация проблем и поиск решений

## 1. Существующие проблемные места

 1. Не настроено корректное логирование
 2. Не настроен tracing
 3. Не настроены оповещения о возникших проблемах (в том чилсе если заказ долго находится в работе)
 4. Некорректно настроены статусы заказа, остуствует этап подтверждения получения заказа с производства. (Заказ передан в производство).
 5. Плохое взаимодействие с пользователем и предоставление недостаточного обьема информации.
 6. Отсуствие кеширования для данных. Что замедляет работу приложения и создает дополнительную нагрузку на БД.
 7. Все взаимодействие в приложении происходит не в режиме реального времени и оператором необходимо переодически обновлять данные для получения актуальной информации о заказах.
 8. Пользователи напрямую взаимодействуют с MES API. При обращении к сервису напрямую отстувует управление трафика сервис можно лекго нагрузить и применить "DDos-атаку".
 9. Релизы выпускают нестабильно, что увеличивает Lead Time, недовольство клиентов и техдолг.

## 2. Потенциальные проблемные места
1. Всего один инстанс БД. При его отказе приложение полностью выйдет из строя и мы не сможем получать заказыва.
2. Всего один инстанс RabbitMQ. При его отказе расчеты изделий встанут и часть заказов может быть потеряна.
3. Всего один инстанс MES. При его отказе расчеты изделий встанут и часть заказов может быть потеряна.
4. Всего один инстанс S3. При его отказе расчеты изделий встанут и часть заказов может быть потеряна.  
5. Нагрузка постоянно растет, а в приложении не настроены никакие системы восстановления, автоскейлинга и работы с высокой нагрузкой.
6. Пользователи API обращаются к системе MES, а в последствии, после обработки, создают заказ в CRM.
7. Проблемы с тестированием.

## 3. Инициативы, которые необходимы для устранения нежелательных ситуаций

1. Необходимо внедрить средства логирования/мониторинга/трейсинга системы. Это поможет понять причины воспроизведения проблем и оперативно реагировать на них.
2. Необходимо внедрить систему алертинга ни только технического, но и бизнесового. Это поможет понять причины воспроизведения проблем и оперативно реагировать на них. Также с бизнесовой точки зрения это поможет для оперативного взаимодействия с клиентом/производством и улучшить пользовательский опыт.
3. Необходимо доработать статусы заказа и внедрить систему клиентского мониторинга, которая будет давать подробную информацию о заказах клиента.
4. Необходимо внедрить систему кеширования для уменьшения нагрузки и предоставление более быстрого ответа пользователю.
5. Необходимо доработать приложение и реализовать взаимодействие в режиме реального времени, рекомендуется использовать WebSocket'ы для двунаправленного потока взаимодействия.
6. Необходимо реализовать ApiGateway с асинхронной очередью для пользователей API для взаимодействия с системой MES. Это поможет контролировать нагрузку на систему и управлять доступами пользователей.
7. Необходимо пересмотреть процесс подготовки релизов и организации работы команды.
8. Необходимо использовать несколько инстансов БД/RabbitMQ/MES/S3. Отказ одного из перечисленных контейнеров вызовет серьезные проблемы, потерю заказов и данных.
9. Необходимо пересмотреть инфраструктуру приложения и внедрить автоматическое масштабирование при высоких нагрузках на систему.
10. Логика работы с пользователями API должна быть другая. Изначально заказ должен создаваться в CRM, а на его основе уже должен происходить расчет. В противном случае заказ может быть потерян.
11. Необходимо внедрить автоматическое тестирование, что минимизирует человеческий фактор при проведении тестов. Необходимо расширить пулл всевозможных тестов, для отлавливания возникших проблем до подготовки релиза. После внедрения автоматического тестирования необходимо внедрить такие тесы в pipeline для отлавливания проблем до слияния изменений.

## 4. Какой вы видите целевую архитектуру через полгода?

Для операторов необходимо внедрить обновление контента в режиме реального времени. Для этого рекомендую использовать WebSocket'ы для получения контента и взаиможействия с ним в режиме реального времени.
