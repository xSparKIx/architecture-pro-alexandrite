# Планирование: анализ, идентификация проблем и поиск решений

## 1. Существующие проблемные места

 1. Не настроено корректное логирование
 2. Не настроен tracing
 3. Не настроены оповещения о возникших проблемах (в том чилсе если заказ долго находится в работе)
 4. Некорректно настроены статусы заказа, отсутствует этап подтверждения получения заказа с производства. (Заказ передан в производство).
 5. Плохое взаимодействие с пользователем и предоставление недостаточного обьема информации.
 6. Отсуствие кеширования для данных. Что замедляет работу приложения и создает дополнительную нагрузку на БД.
 7. Все взаимодействие в приложении происходит не в режиме реального времени и оператором необходимо переодически обновлять данные для получения актуальной информации о заказах.
 8. Пользователи напрямую взаимодействуют с MES API. При обращении к сервису напрямую отсутствует управление трафика сервис можно лекго нагрузить и применить "DDos-атаку".
 9. Релизы выпускают нестабильно, что увеличивает Lead Time, недовольство клиентов и техдолг.

## 2. Потенциальные проблемные места
1. Всего один инстанс БД. При его отказе приложение полностью выйдет из строя и мы не сможем получать заказыва.
2. Всего один инстанс RabbitMQ. При его отказе расчеты изделий встанут и часть заказов может быть потеряна.
3. Всего один инстанс MES. При его отказе расчеты изделий встанут и часть заказов может быть потеряна. 
4. Нагрузка постоянно растет, а в приложении не настроены никакие системы восстановления, автоскейлинга и работы с высокой нагрузкой.
5. Пользователи API обращаются к системе MES, а в последствии, после обработки, создают заказ в CRM.
6. Проблемы с тестированием.

## 3. Инициативы, которые необходимы для устранения нежелательных ситуаций

1. Необходимо пересмотреть процесс подготовки релизов и организации работы команды.
2. Необходимо внедрить средства логирования/мониторинга/трейсинга системы. Это поможет понять причины воспроизведения проблем и оперативно реагировать на них.
3. Необходимо внедрить систему алертинга ни только технического, но и бизнесового. Это поможет понять причины воспроизведения проблем и оперативно реагировать на них. Также с бизнесовой точки зрения это поможет для оперативного взаимодействия с клиентом/производством и улучшить пользовательский опыт.
4. Логика работы с пользователями API должна быть другая. Изначально заказ должен создаваться в CRM, а на его основе уже должен происходить расчет. В противном случае заказ может быть потерян.
5. Необходимо реализовать ApiGateway с очередью для пользователей API для взаимодействия с системой MES. Это поможет контролировать нагрузку на систему и управлять доступами пользователей.
6. Необходимо внедрить автоматическое тестирование, что минимизирует человеческий фактор при проведении тестов. Необходимо расширить пулл всевозможных тестов, для отлавливания возникших проблем до подготовки релиза. После внедрения автоматического тестирования необходимо внедрить такие тесы в pipeline для отлавливания проблем до слияния изменений.
7. Необходимо использовать несколько инстансов БД/RabbitMQ/MES/S3. Отказ одного из перечисленных контейнеров вызовет серьезные проблемы, потерю заказов и данных.
8. Необходимо пересмотреть инфраструктуру приложения и внедрить автоматическое масштабирование при высоких нагрузках на систему.
9. Необходимо внедрить систему кеширования для уменьшения нагрузки и предоставление более быстрого ответа пользователю.
10. Необходимо доработать статусы заказа и внедрить систему клиентского мониторинга, которая будет давать подробную информацию о заказах клиента.
11. Необходимо доработать приложение и реализовать взаимодействие в режиме реального времени, рекомендуется использовать WebSocket'ы для двунаправленного потока взаимодействия.

## 4. Какой вы видите целевую архитектуру через полгода?

1. Внедрены системы мониторинга и алертинга
2. Пересмотрена логика работы приложения и оформления заказов
3. Внедрен ApiGateway с очередью
4. Поднято несколько инстансов баз данных/RabbitMQ и настроена репликация
5. Реализован автоскейл основных сервисов и проработаны алгоритмы работы системы в случае отказа
6. Внедрена система кеширования
7. Доработана система пользовательского мониторинга и статусы заказа
